# Phase 02.1 Plan 02: Data Layer - eventId Stamping & Filtering Summary

## What Was Built

Implementation of multi-event data partitioning across all Cat/Score data types. Every record created after deploy is automatically stamped with the active eventId. Every query filters by the active eventId server-side, ensuring judges always see the correct event's data.

**One-liner:** Added eventId field to Cat, Score, ClassScore, FitShowScore, and all audit entry types. Implemented server-side stamping on create and filtering on all list/lookup queries. Created production backfill migration script.

## Architecture

### Server-Side Event Stamping
- `createCat`, `createScore`, `createClassScore`, `createFitShowScore` all call `getActiveEventId()` before writing
- EventId is stamped on the primary item AND all secondary index items (CAT#, JUDGE#, etc.)
- Client cannot override or specify eventId — all writes are tagged with the active event automatically

### Event-Scoped Queries
All list/lookup operations now filter by eventId:
- `listCats(eventId: active)`
- `listAllScores(eventId: active)` 
- `getScoresByCage(cageNumber, eventId: active)` — **fixes cage reuse cross-event leak**
- `listAllClassScores(eventId: active)`
- `getClassScoresByCage(cageNumber, eventId: active)` — **fixes cage reuse cross-event leak**
- `listFitShowScores(eventId: active)`

### Audit Trail Preservation
Existing score audit trails (scoreAuditEntry, classScoreAuditEntry, fitShowScoreAuditEntry) now include eventId so archival and restore operations maintain complete audit history for each event.

### Production Backfill
`migrateBackfillEventId.ts` runs once on production to:
1. Bootstrap an Event record if needed (bootstrap event with timestamp of first deployment)
2. Set SETTINGS/ACTIVE_EVENT pointer to the bootstrap event
3. Scan all legacy Cat/Score/ClassScore/FitShowScore items (paginated)
4. Add eventId field to items missing it (idempotent via ConditionExpression)
5. Recreate all secondary index items with eventId included

**Invocation:** `TABLE_NAME=cat-voting-table npx tsx infrastructure/lambda/migrateBackfillEventId.ts`

## Risk Mitigations

### Cross-Event Cage Number Leak (RESEARCH Pitfall 3)
**Risk:** Cage numbers reused across events (e.g., Cage 1 in 2024 and Cage 1 in 2025) would collide in queries.
**Mitigation:** `getScoresByCage` and `getClassScoresByCage` now filter by BOTH `cageNumber` AND `eventId`. ✓ Fixed

### Dual Source of Truth
**Risk:** eventId passed as query argument could drift from server-side active event.
**Mitigation:** All mutations and queries resolve eventId server-side via `getActiveEventId()`. Clients cannot pass eventId. ✓ Mitigated
