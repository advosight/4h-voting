## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Judge browser -> AppSync GraphQL API | Untrusted client input crosses here for every score field and the existing-score lookup |
| Judge browser -> AppSync subscriptions | Push channel; payload content is server-controlled but connection lifecycle is client-managed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | FitShowScoringForm score inputs | medium | mitigate | Server-side `validateFitShowScoreInput` in fitShowScoreResolver.ts already rejects out-of-range values regardless of client UI; this task must not remove or weaken it (unchanged file) |
| T-01-02 | Spoofing | createFitShowScore/updateFitShowScore judgeId | medium | mitigate | Server derives judgeId/judgeName from the Cognito auth context (`getJudgeId(userContext)`), ignoring any client-supplied value; unaffected by this task |
| T-01-03 | Information Disclosure | New getFitShowScoresByCat lookup in FitShowScorePage | low | accept | Resolver already filters to `isFinalized \|\| judgeId === currentJudgeId` for judge callers; the new client-side lookup only narrows further to the current judge's own entry, so no new exposure |
| T-01-04 | Denial of Service (resource leak) | FitShowScoringPage subscriptions | low | mitigate | Cleanup function unsubscribes both channels and clears the interval on unmount, mirroring FitShowScoreLeaderboard.tsx's tested pattern |
</threat_model>
