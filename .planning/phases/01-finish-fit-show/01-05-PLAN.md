  <files>src/styles/responsive.css, src/styles/fit-show-scoring.css, index.html</files>
  <read_first>
    src/styles/responsive.css (`.device-mobile { --touch-target-min: 44px; }` — the value
    to raise), src/styles/fit-show-scoring.css (`@media (max-width: 767px)` block to add
    sizing rules to), index.html (current viewport meta:
    `content="width=device-width, initial-scale=1, shrink-to-fit=no, viewport-fit=cover"`
    — no `maximum-scale` is set today, meaning zoom is not explicitly guaranteed across
    all browsers/PWA contexts)
  </read_first>
  <action>
    In `responsive.css`, change `.device-mobile { --touch-target-min: 44px; }` to `48px`
    (Material Design's 48x48px minimum, per D-07 — this variable already exists and is
    already applied app-wide via the `ResponsiveProvider`'s device-class toggling; raising
    its mobile-tier value is the correct, minimal-blast-radius change). Leave
    `.device-tablet` (40px) and `.device-desktop` (32px) untouched — D-07 is scoped to
    mobile.

    In `fit-show-scoring.css`'s `@media (max-width: 767px)` block, add
    `min-height: var(--touch-target-min); min-width: var(--touch-target-min);` targeting
    the real interactive elements rendered inside the six scoring sections: number inputs
    (`input[type="number"]`), the section's own buttons if any, and (scoped to this file)
    the section header's clickable area — so the 48px minimum actually reaches the
    elements a judge taps, not an unused class name from the pre-built, never-wired
    CSS file's aspirational selectors.

    In `index.html`, change the viewport meta tag's content from
    `"width=device-width, initial-scale=1, shrink-to-fit=no, viewport-fit=cover"` to
    `"width=device-width, initial-scale=1, maximum-scale=5.0, shrink-to-fit=no,
    viewport-fit=cover"` — this is an additive change to one existing line; no other
    meta tags change.
  </action>
  <verify>

  </verify>
