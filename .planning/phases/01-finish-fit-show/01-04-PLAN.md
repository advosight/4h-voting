<objective>
Give admins the two D-12/D-11 capabilities the phase goal requires and that plan 01-02
only built server-side support for: a one-click "Finalize Scoring" action that locks every
submitted score, and the ability to override a finalized score with a captured reason and
a viewable audit changelog — while confirming D-10's visual states (already implemented in
FitShowScoringPage.tsx) reflect the new admin-driven finalization correctly.

Purpose: Plan 01-02 built `finalizeAllFitShowScores` and a reason-aware
`finalizeFitShowScore`, but nothing in the UI calls them yet. Without this plan, D-12's
"manual admin action to finalize all scores" and D-11's "admin override with audit trail,
viewable in a score history/changelog" have no way to be exercised by a real admin.

Output: FitShowScoringPage.tsx has an admin-only "Finalize All Scores" control and,
per finalized score, "Override" and "View History" controls; FitShowScoringForm accepts an
override reason; FitShowScoreAuditHistory is wired to the real audit query.
</objective>

|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | Finalize-all / Override / View History controls | high | mitigate | Buttons are hidden client-side by role, but every mutation they call (`finalizeAllFitShowScores`, `updateFitShowScore`) is independently role-checked server-side (plan 01-02, existing resolver code); a non-admin who forces the button to render via devtools still gets a PermissionError from the server |
| T-04-02 | Repudiation | Admin override without a reason | medium | mitigate | `window.prompt` requires a non-empty reason before navigation proceeds; an empty/cancelled prompt aborts the override entirely, so every override that reaches the server carries a `modificationReason` |
